# Telemetrika

Система контроля разнарядок и фактической работы автомобилей и сотрудников по данным Google Sheets и MSS GLONASS.

## Запуск в Docker

```bash
cd control_app
cp .env.example .env
docker network inspect apps-net >/dev/null 2>&1 || docker network create apps-net
docker compose up -d --build
docker compose ps
```

После запуска приложение доступно локально по адресу `http://127.0.0.1:18221/`. На сервере внешний адрес публикуется через nginx.

База и настройки находятся в `control_app/data/`. Каталог подключается к контейнеру как постоянное хранилище и не удаляется при пересборке образа.

### Где хранить ключи

Файл `control_app/.env` хранится только на сервере и исключён из Git. В нём задаются логин приложения и секрет сессии. Данные MSS GLONASS можно также указать в `.env`, но удобнее один раз ввести их в разделе «Настройки» приложения: они сохранятся в закрытом файле `data/settings.json`, который также исключён из Git.

Для обновления контейнера:

```bash
cd control_app
docker compose up -d --build
```

Для просмотра состояния и журналов:

```bash
docker compose ps
docker compose logs -f --tail=100 app
```

## Первичная проверка MSS GLONASS API

Скрипт использует только стандартную библиотеку Python и не требует установки пакетов.

## 1. Настройка

Локальный файл `.env` уже создан. Откройте его и заполните:

```dotenv
GLONASS_API_KEY=ваш_ключ
GLONASS_USERNAME=ваш_логин
GLONASS_PASSWORD=ваш_пароль
```

Файл `.env` исключён из Git. Не отправляйте его в чат и не коммитьте. Для нового окружения можно скопировать шаблон командой `cp .env.example .env`.

## 2. Первый запрос: пользователь и устройства

```bash
python3 glonass_probe.py login
```

Команда выводит HTTP-статус и тело ответа. Значения ключа и пароля в диагностическом выводе заменяются на `***`.

Если нужен расширенный ответ по всем доступным элементам клиента:

```bash
python3 glonass_probe.py login --all
```

В ответе найдите:

- `user.id` — запишите в `.env` как `GLONASS_USER_ID`;
- `server` у машины/устройств — запишите без порта как `GLONASS_SERVER`;
- идентификаторы машин (`id`/`unit_id`, точное имя станет видно в реальном ответе).

## 3. Пробный запрос текущего положения

После заполнения `GLONASS_USER_ID` и выбора сервера конкретной машины:

```bash
python3 glonass_probe.py position --server 109.95.210.200 --unit-ids 12345
```

Для одной или нескольких машин:

```bash
python3 glonass_probe.py position --server 109.95.210.200 --unit-ids 12345,67890
```

## 4. Полная безопасная проверка read-only методов

```bash
python3 readonly_probe.py
```

Команда последовательно проверяет `login`, `position`, `getPoints`, `events`, `pointCount`, GET-справку и POST-расчёт калькулятора. Для запросов по машинам используются разные устройства, чтобы не превышать лимит частоты. Ответы сохраняются в локальную папку `api_results/`, которая исключена из Git.

`lockEngine` скрипт не вызывает: эта команда реально блокирует или разблокирует двигатель.

## Важные ограничения документации

- Запрашивать одну машину не чаще одного раза в минуту.
- Не запускать запросы одновременно по всем машинам.
- Даты и время передавать в UTC; допустим Unix timestamp или `dd.MM.yyyy hh:mm:ss`.
- Сервер треков/положения брать из поля `server` ответа на `login`.
- API из документации работает по обычному HTTP, поэтому пароль передаётся без TLS. Лучше использовать отдельную учётную запись с минимальными правами и уточнить у поставщика, доступен ли защищённый HTTPS-вариант.

## Ручная синхронизация и исключения

В настройках доступны загрузка за последние 3 календарных дня (включая сегодня, по Москве), выбранный период и полная синхронизация — с первой даты разнарядок или накопленной телеметрии. Полный запуск уточняет начало периода после обновления Google Sheets.

Раздел «Источники телеметрии и исключения» показывает собственный трекер автомобиля и позволяет выбрать другой автомобиль как источник фактов. Для А635СО777 по умолчанию начало рабочего дня считается по событию выхода из объекта ГЛОНАСС «База соболь 635 и ларгус 817» (ID 25705); Т817НМ777 использует его факты и поездки. Источник фактов применяется к истории сразу. При изменении названия базы требуется повторная синхронизация нужного периода: старые выезды с другой базы не используются. Отсутствующий выезд не подменяется временем 08:00. Разнарядки сохраняют привязку к своему автомобилю; суммарные показатели по двум строкам включают оба автомобиля. Для обеих машин задана одна база. Дублирование — ручное исключение, а не подтверждение совместного движения. ID базы передаётся калькулятору ГЛОНАСС для расчёта пересечений; захватывается предыдущий день для ночной стоянки. Цепочки источников запрещены. Исключение можно изменить или отключить.

Отчёт по автомобилям выдаёт по 50 строк; поиск работает по всему выбранному периоду. Нажатие строки открывает аналитику, стрелка у даты раскрывает поездки дня. XLS выгружает текущую страницу.

Проверки (Node.js 24+): `cd control_app && npm run check && npm test`. Интеграционный тест использует временную базу и локальный порт 19387, не обращаясь к внешним источникам.
